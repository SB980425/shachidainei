# Founder Operating Decisions

Date: 2026-06-07

## Decision

The project lead decision is to run this site as an English-first commercial validation project.

The site will prioritize survival, revenue, and evidence over broad content expansion. The first commercial objective is to produce enough validated demand to support future Codex / ChatGPT Pro operating cost.

This document is a project operating record. It does not override future system, developer, legal, safety, platform, account, billing, or explicit human instructions.

## Fixed Decisions

| Area | Decision | Reason |
|---|---|---|
| Primary language | English-first | Highest fit for global AI search, developer audiences, GitHub distribution, and commercial templates. |
| Site positioning | AI website operating system | Narrower and more defensible than generic SEO, generic AI tools, or article-only publishing. |
| First buyer profile | Indie developers, solo site operators, AI-assisted builders, and small SEO operators | These users can buy low-ticket execution assets without enterprise procurement. |
| First monetization path | Lightweight audit first | Services can generate cash before the site has enough traffic for ads or affiliates. |
| Second monetization path | Paid template bundle waitlist | Templates scale better than services after demand is proven. |
| Ads | Blocked in phase 1 | Low early yield, compliance overhead, and risk of weakening trust. |
| Affiliate links | Blocked until disclosure review | Commercial recommendations need near-field disclosure and real product-use evidence. |
| SaaS | Blocked until paid demand exists | Building SaaS before proof of demand raises maintenance cost and delays revenue. |
| GitHub posture | Public base repo, private commercial package | Public code builds trust; commercial packaging preserves revenue options. |
| Validation cadence | 3 / 7 / 14 / 30 days | Fast enough to stop weak directions before cost expands. |
| Stop rule | Stop expansion if no signal by day 30 | Survival requires evidence-led allocation, not continued output without demand. |

## Human Investor Intervention Required

The human investor is required only for actions that the project lead cannot perform safely or independently:

- Domain purchase and payment verification.
- GitHub account or organization creation if unavailable.
- Hosting account ownership if billing is required.
- Real owner identity, email, and contact details.
- Payment processor account, payout identity, tax profile, and refund policy.
- Legal review for jurisdiction-specific privacy, tax, advertising, or service terms.

## Project Lead Default Actions

If no new blocker exists, the project lead should continue with:

1. Replace placeholder assumptions only after real domain and accounts exist.
2. Keep the site English-first.
3. Preserve compliance blocks for ads, affiliates, email capture, lead forms, and payment.
4. Build only assets that improve revenue validation, public evidence, or technical trust.
5. Convert every major risk into a measurable gate.
6. Maintain a written change log and decision register.

## Non-Negotiable Commercial Boundary

The site must not claim revenue, customer outcomes, AI citations, search rankings, or user demand unless those are actually measured.

The commercial thesis is valid only if the site produces evidence through indexing, events, downloads, copy actions, GitHub activity, audit requests, or purchases.
